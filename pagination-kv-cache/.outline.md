# Outline — pagination-kv-cache

## Thèse centrale
La gestion du KV-cache a cessé d'être de l'allocation mémoire pour devenir de la **mémoire virtuelle** : PagedAttention importe la pagination de l'OS (blocs, table de pages, copie-sur-écriture), RadixAttention y ajoute le partage automatique de préfixes via un arbre radial, et c'est ce substrat — pas une optimisation de service greffée après coup — qui a rendu possible le *prompt caching* facturé −90 % en production, et qui bute aujourd'hui sur le **mur du préfixe**.

Distinct de `kv-cache` (qui listait PagedAttention/RadixAttention parmi dix sujets) : ici les deux mécanismes sont lus ligne à ligne et reliés à l'économie du cache + la limite du préfixe (CacheBlend, LMCache).

## Plan (7 sections)
1. **Un tableau contigu qui gaspille 60-80 %** — réservation contiguë `max_seq_len`, trois gaspillages (réservé-non-utilisé, interne, externe), diagnostic vLLM. Lead : l'inférence est *memory-bound*, et jusqu'en 2023 on jetait la majorité de la mémoire par fragmentation.
2. **PagedAttention : importer la mémoire virtuelle** — blocs 16 tokens, table de blocs logique→physique, indirection, gaspillage < 4 %, l'attention qui lit des blocs non contigus, analogie OS page/frame/page table, ×24 vs HF, ×2-4 vs Orca. Lead : l'idée n'est pas nouvelle — c'est la pagination des systèmes d'exploitation, appliquée au cache d'attention.
3. **Copie-sur-écriture : partager puis diverger** — échantillonnage parallèle / beam search, blocs du prompt partagés jusqu'à divergence, ref count, copie à l'écriture, ~55 % d'économie. Lead : un prompt, N sorties — pourquoi payer N fois la mémoire du prompt.
4. **RadixAttention : du partage intra-requête au partage inter-requêtes** — arbre radix du KV-cache, insertion/recherche/éviction LRU des feuilles, cache-aware scheduling, ×5-6,4 débit, workloads (multi-tour, few-shot, arbre-de-pensée). Lead : PagedAttention partage *dans* une requête ; RadixAttention partage *entre toutes*.
5. **APC en production : le hash chaîné** — vLLM automatic prefix caching, hash(parent_hash, token_ids, extra_keys : LoRA/multimodal/cache_salt), match exact token-par-token, éviction du dernier bloc d'abord. Lead : identifier un préfixe réutilisable sans parcourir un arbre — juste un hash qui chaîne.
6. **L'économie du prompt caching** — Anthropic (public beta 14 août 2024, GA 17 déc 2024 ; read 0,1× = −90 % ; write 1,25× TTL 5 min / 2,0× TTL 1 h ; min 1024 tokens ; reset au read), OpenAI (−50 % auto), le cache comme ligne de facturation, l'incitation à mettre le préfixe stable en tête. Lead : quand la mémoire devient un produit facturé, l'architecture de service devient l'architecture du prompt.
7. **Le mur du préfixe et la hiérarchie mémoire** — seuls les *préfixes* se partagent ; en RAG les chunks concaténés (sauf le 1er) ne sont pas des préfixes → cache quasi inutile ; CacheBlend (recompute ~15 % des tokens critiques, EuroSys 2025 Best Paper, TTFT −2,2-3,3×, débit ×2,8-5, ~100 % hit), Prompt Cache (MLSys 2024, modules), LMCache (couche persistante DRAM/SSD/remote, RAG ×4,5), hiérarchie HBM/DRAM/SSD, KV-as-a-service + isolation cross-tenant. Trajectoires.

## Schémas (7) + zones cliquables
- **SCHEMA-01 · Anatomie du gaspillage** (landscape) — barre de mémoire GPU : réservée `max_seq_len` vs réellement utilisée, 3 bandes de gaspillage. Régions : `reserve-slot` (sur-réservation), `internal-waste` (fragmentation interne du dernier bloc), `external-waste` (trous entre séquences), `used` (KV réel).
- **SCHEMA-02 · La table de blocs** (landscape) — séquence logique (blocs 0,1,2…) → table de blocs → blocs physiques dispersés dans le pool. Régions : `logical-blocks`, `block-table` (indirection), `physical-pool`, `os-analogy` (page/frame).
- **SCHEMA-03 · Copie-sur-écriture** (landscape) — un prompt partagé, N séquences échantillonnées, ref count, bloc dupliqué au point de divergence. Régions : `shared-prompt`, `ref-count`, `fork-point` (divergence), `cow-copy`.
- **SCHEMA-04 · L'arbre radix du cache** (square) — racine (système prompt), branches (conversations/few-shot), feuilles (générations récentes), flèche d'éviction LRU. Régions : `root-prefix`, `shared-branch`, `leaf-eviction` (LRU), `cache-aware-sched`.
- **SCHEMA-05 · Le hash chaîné** (landscape) — chaîne de blocs, chaque hash = f(hash parent, token_ids, extra_keys), match exact, salt/isolation. Régions : `chained-hash`, `extra-keys` (LoRA/multimodal/salt), `exact-match`, `last-block-evict`.
- **SCHEMA-06 · La structure tarifaire du cache** (landscape) — timeline d'une conversation multi-tour : write initial (1,25×/2,0×) puis reads amortis (0,1×), courbe de coût cumulé cache vs sans cache, TTL. Régions : `cache-write`, `cache-read`, `ttl-reset`, `break-even`.
- **SCHEMA-07 · Le mur du préfixe** (landscape) — RAG : concaténation système+chunkA+chunkB+question ; seul le préfixe système hit ; CacheBlend recompute ~15 % ; à droite la hiérarchie mémoire HBM/DRAM/SSD/remote. Régions : `prefix-hit`, `non-prefix-miss`, `cacheblend-recompute`, `memory-hierarchy`.
